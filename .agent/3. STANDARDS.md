# 3. 架构规范与红线禁令 (STANDARDS)

## 架构边界与职责划分

```
[音频输入] 
   │
   ▼
[1. 声学感知层 (Python/Node)] ──> 只陈述客观事实 (物理能量、音高Hz、真实起音瞬态)
   │                           严禁任何主观编舞映射代码！
   ▼
[2. 真实 LLM 编舞大脑]       ──> 拥有绝对主观审美权 (音乐意象理解、动势构思、节奏留白、手势设计)
   │                           纯粹调用大模型 API / 浏览器大模型推理！
   ▼
[3. 运动学安全沙盒 (Linter)]  ──> 仅作解剖学底线兜底 (拦截手腕扭断、同拍同位重叠、物理打结)
   │                           绝不干预艺术风格！
   ▼
[4. 3D Web 视听渲染层]       ──> 忠实复现与第一人称试玩
```

## 硬性工程禁令

1. **严禁在代码中写死动作逻辑**：禁止出现任何类似“音高升高放第 2 层”、“鼓点就下砍”的硬编码分支。
2. **时序锁相严禁经验主义**：任何音频必须先做物理瞬态探测与真实起始偏移行程测定（Phase-Lock），严禁假设 `timeOffset=0`。
3. **文档与代码双闭环**：任何阶段性技术决断（ADR）与关键踩坑，必须立即同步落盘至 `.agent` 体系。

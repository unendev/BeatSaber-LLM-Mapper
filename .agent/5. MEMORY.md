# 5. 智慧与防踩坑指南 (MEMORY)

## 核心反思与防踩坑铁律

### 1. 警惕“程序员假扮谱师”的傲慢死局
- **教训**：当试图用几行代码去归纳音乐（例如“音调高就放上层，音偏右就往右放”）时，系统立刻退化成了低劣的“打地鼠算法”。
- **铁律**：代码绝对不要替谱师做美学决断。音乐中的高音可能是为了蓄力从天劈砍，也可能是为了空拍留白。这种主观意象和艺术审美，必须交由 LLM 的大模型神经网络来推理。

### 2. 真实物理时序三要素：BPM、起始留白与瞬态对齐
- **暗礁**：千万不要盲信标签或固定预设的 BPM。
- **验证标准**：必须通过 `librosa.onset` 计算真实物理击打间距（Inter-Onset Interval），并测量音频头部真实的起音时间差（如本曲的 0.7314s）。时钟一旦偏差 5%，后面所有小节全盘皆崩。

### 3. WebGL 贴图混合踩坑
- **暗礁**：在 Three.js 中，将带透明通道的 CanvasTexture 作为 `map` 挂在有高自发光（Emissive）的 `MeshStandardMaterial` 上时，透明区域会被自发光与漫反射颜色完全涂抹，导致图案不可见。
- **解法**：Canvas 自身绘制纯色底背景与高对比度白色边框，使用 `MeshBasicMaterial` 或严格配置 `alphaTest: 0.5` / `transparent: true`。
